- 应用产物默认**仅存本地工作区**，无自动云端备份：`.workbuddy/applications.yaml` 登记 + `.wbapp_*.genie` 元数据（appId / localDir / entryHtml），代码实体在 `localDir`。

## 修复：刀补偏置轨迹被拉斜（用户反馈）

**现象**：方形轮廓 `G41 D01 X0 Y0 → Y50 → X50 → Y0 → X0 → G40`，橙色偏置层呈平行四边形，四条边都是斜的。

**根因**：`compRuns` 先把同侧补偿段合并成一条折线，再用 `base[i-1]`、`base[i+1]` 求每点切向。直线段只有两个端点，两端点的相邻点都来自**相邻的另一条边**，切线取到跨角平均方向，于是每条边的两个端点法向都偏了角度 → 整边变斜。（角度处产生的是系统性偏斜，不是接缝尖刺。）

**修法**：改为逐段取自身法向 —— 直线用恒定方向，圆弧用段内采样差分；拐点用角平分线求真实偏移交点 `m = (n1+n2)/(1+n1·n2)`，偏移点 = 角点 + r·m。另加真机语义：建立刀补那一段的**起点保持编程点**（刀心从编程点切入偏置位置），只有终点偏置。

**验证**：该程序偏置后为 x∈[-5,55]、y∈[-5,55] 的严格平行方形，进刀从 (-20,-20) 斜切到 (-5,2.07)。新增 6 条针对性断言（四角坐标 + 左边两顶点 x 相同 + 进刀起点不偏置），回归 **111 项 0 失败**。

**已知表现**：G40 段不参与偏置，所以橙线终点停在 (0,-5) 与蓝线角点 (0,0) 有 5mm 缺口——这是真机退刀行为（G40 段刀心从补偿位置回到编程点），不是 bug。
