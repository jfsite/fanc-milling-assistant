# 方案：图纸 → SVG（作为出程序的唯一入口）

> 结论先行：**不要再让模型直接"看图出点列再出程序"**。把目标改成"把图纸变成一份可信的 SVG"，
> 程序生成继续走已有的确定性链路（`parseSvgIR` → `irToNC` → 43 条校验 → 刀轨）。
> 理由是：现在的瓶颈 100% 在"图 → 几何"这一步，而几何之后的部分已经验证过（194~210 项断言）。

---

## 1. 为什么必须分两层

| 环节 | 现在的做法 | 问题 |
|---|---|---|
| 图纸 → 几何 | 视觉模型直接输出**点列**（每轮廓 8~120 个点） | 点列不可解释：错了不知道错在哪，只能重来；R100 会被描成折线；尺寸靠猜 |
| 几何 → 程序 | 本地确定性生成（G41/层数/孔判定/校验） | **这一层是好的，不要动** |

分两层之后，中间产物 **SVG** 带来三个直接好处：

1. **可看**：能和原图叠在一起比对，错在哪一眼能看出来；
2. **可改**：改一个 R 值、挪一个圆心，比改 200 个点现实；
3. **可存档**：一个班几十个零件，SVG 存下来就是题库资产，下次直接调用，不再调模型。

---

## 2. 三条路线（已评估）

| 路线 | 做法 | 精度 | 成本 | 结论 |
|---|---|---|---|---|
| **A 位图自动描摹** | 二值化 + 轮廓跟踪（potrace 类） | 低 | 中（要内联 ~1500 行，或引 CDN） | ❌ 不可用 |
| **B 模型出图元 → 本地拼 SVG** | 模型输出 line/arc/circle + 标注原文；本地合成 SVG | 中高 | 低（~600 行） | ✅ **主线** |
| **C 人工录入** | 画布点选 / 填基点坐标表 | 高 | 中 | ✅ 兜底 + 教学价值 |
| D 直接要矢量源 | DXF / PDF 提取 | 最高 | 低（DXF 易，PDF 需库） | ✅ 有源时优先 |

**A 为什么不可用**：工程图是"线"构成，描摹得到的是每根线的**两条边**（线宽），得到的是双线闭合环；
而且尺寸线、中心线、剖面线、图框会一起被描进去 —— 对 CNC 是灾难，等于把标注也铣出来。
除非做骨架化（centerline），那是另一个量级的工作量，且中文标注仍会变成乱码轮廓。

---

## 3. 推荐方案：B 主线 + C 兜底

### 3.1 数据流

```
图纸(位图/照片) ──视觉模型──> primitives JSON ──本地合成──> outline.svg
                                    │                          │
                              标注原文/置信度              叠加预览(原图+轮廓)
                                    │                          │
                                    └──── 人工修正(R值/圆心/尺寸) ┘
                                                               │
                                              parseSvgIR → irToNC → 校验/刀轨
```

### 3.2 图元 schema（实测可用）

一次真实探测（T3-1，v1.6.5 环境）得到：

```json
{"unit":"mm","confidence":0.86,
 "primitives":[
   {"type":"line","x1":1,"y1":23,"x2":1,"y2":7},
   {"type":"arc","cx":11,"cy":7,"r":10,"a0":180,"a1":270,"dir":"cw"},
   {"type":"line","x1":11,"y1":1,"x2":69,"y2":1},
   {"type":"arc","cx":69,"cy":7,"r":6,"a0":270,"a1":225,"dir":"cw"}],
 "closed":true,
 "dims":[{"text":"80","value":80},{"text":"78-0.05","value":78},
         {"text":"30","value":30},{"text":"8+0.10","value":8},
         {"text":"R9","value":9},{"text":"R100","value":100},{"text":"R25","value":25}],
 "blank":{"w":80,"h":30},
 "notes":"按图面 R9 与 R25 标注位置取角部圆角 R9…"}
```

要点：

- **图元不是点列**：`arc` 带圆心/半径/起止角，几何是闭合解，长度和法向都能精确算；
- **标注原文单独列**：`dims[].text` 是图上真的印着的字，`value` 是解析出的数 —— 这是唯一可信的尺寸来源；
- **`blank` 与轮廓分离**：毛坯不进几何（v1.6.3 起已有这条规则，只是现在能表达得更干净）。

> 这次探测里模型还把 `30` 读成了俯视图宽度（`blank={80,30}`），说明它开始按"标注去理解图面"，
> 而不是按像素比例猜 —— 正是我们要的方向。

### 3.3 本地合成 SVG（确定性）

- `line` → `<path d="M x1 y1 L x2 y2">`；`arc` → `A r r 0 largeArc sweep x2 y2`（由圆心起止角换算端点）；
- **闭合拼接**：按顺序把图元首尾相接，接缝误差 ≤0.05 mm 视为闭合；>0.05 报 `S01 轮廓未闭合（缺口 0.32mm，在第 5、6 段之间）`；
- 方向归一：面积符号判顺逆，外轮廓顺时针、内轮廓逆时针（与 `irToNC` 现有口径一致）；
- 输出两份：`outline.svg`（只含轮廓，进 `parseSvgIR`）与 `preview.png`（叠加用）。

### 3.4 三道本地校验（不进模型）

| 编号 | 检查 | 阻断 |
|---|---|---|
| S01 | 图元首尾闭合（缺口 ≤0.05mm） | 是 |
| S02 | 轮廓自交（线段两两求交，排除相邻段） | 是 |
| S03 | 尺寸一致性：轮廓 bbox 与 `dims` 中引用原文的尺寸偏差 >0.5mm | 否，提示 |

### 3.5 叠加预览（这是本方案的关键 UX）

左边原图（可缩放/平移），右边 SVG 轮廓，或直接把轮廓画在原图上（半透明红/蓝）。
老师一眼就能判断"这条 R100 是不是被拉直了"，然后只改那一段。

### 3.6 修正回路（C 兜底）

三种改法，按成本递进：

1. **改数值**：表格里列出所有图元（R 值、圆心、端点），直接改数字 → 重新合成；
2. **改尺寸**：填「零件长/宽」，触发等比校准；
3. **重录一段**：图上点两个端点 + 输入 R，替换某一段图元；
4. **全手工**：基点坐标表（像 2-87 那种书上给了 A~E 的图，直接填，精度最高）。

## 4. 风险与边界

| 风险 | 现状 | 对策 |
|---|---|---|
| 模型把大圆弧画成直线 | **已实测**：T3-1 的 R100 两侧被简化成直线 | 提示词强制"每条可见弧线都要有 arc 图元"；叠加预览里人为核对；S03 报长度偏差 |
| 模型读错标注 | 会 | `dims` 只认原文；S03 交叉校验；人工改一个数即可 |
| 多视图/立体图混排 | 已改善（只取俯视图） | 保留该规则 |
| 书页照片 | 87 秒、形状偏 | 先裁剪再上传；后续可加透视校正 |
| 图元顺序错乱 | 可能 | 拼接时按端点距离贪心排序，接不上就报 S01 |

---

## 5. 分期

| 期 | 内容 | 估工 |
|---|---|---|
| **M1** | 图元 schema + 本地合成 SVG + 叠加预览 + S01/S02 | 主体 ~500 行 |
| **M2** | 图元编辑表（改 R/圆心/端点）+ S03 尺寸一致性 | ~200 行 |
| **M3** | DXF 导入（纯文本解析）+ PDF 矢量提取 | ~300 行 |
| **M4** | 位图描摹兜底（仅当模型不可用时） | 视需要 |

M1 做完就能替代现在的"点列出程序"路径，且中间产物可存档复用。

---

## 6. 需要确认

1. **SVG 是否作为唯一入口**：以后位图识别也先转 SVG，再由 SVG 出程序？（推荐是）
2. **要不要保留"点列直出程序"**：作为模型不可用时的降级路径，还是彻底删掉？
3. **是否要 DXF**：如果老师手头有 CAD 源文件，DXF 导入是零误差路径，优先级可以提前。
